# SsangBak 운영 변경 기록

코드의 모든 커밋을 반복 기록하지 않는다. 향후 작업자가 알아야 하는 운영 원칙, 구조 변경, 중요한 결정만 이유와 함께 기록한다.

## 2026-09-19 — 유료광고 파일럿 방향과 클릭 측정 확정

### 결정

- 현재 판매 상품을 비교하는 쇼핑커넥트형 랜딩을 1차 파일럿으로 정했다.
- 숙박 예약 제휴는 외부 사이트·제휴 상태 확인 후 2차 후보로 두었다.
- 프로그램 다운로드·정부 신청·조회 글은 계속 작성하되 직접 전환이 없는 상태에서는 유기 검색을 우선한다.
- GA4에 `affiliate_outbound_click`과 `cta_click`을 추가했다.

### 이유

- 구매 수수료가 있는 상품형 콘텐츠가 순수 애드센스보다 광고비와 수익의 인과관계를 측정하기 쉽다.
- 기존 폴드8 제휴 글은 사전예약이 종료돼 현재 광고 랜딩으로 적합하지 않다.
- 외부 상품 이동은 구매가 아니므로 보조 전환으로만 취급해야 한다.

## 2026-09-19 — 프로젝트 기억 구조 도입

### 변경

- 프로젝트 루트에 `AGENTS.md`를 추가했다.
- `PROJECT_SPEC.md`, `CURRENT_STATUS.md`, `ROADMAP.md`, `CHANGELOG.md`로 명세·현황·계획·결정을 분리했다.
- 기존 콘텐츠 표준과 자동화 계획을 새 문서에서 참조하도록 연결했다.

### 이유

- 기존에는 유용한 문서가 여러 개 있었지만 새 Codex 작업이 반드시 읽도록 하는 진입점이 없었다.
- 7~8월에 작성된 상태 문서와 9월의 실제 코드·자동화 상태가 어긋나기 시작했다.
- 장기 운영에서 대화 기억보다 버전 관리되는 프로젝트 상태를 기준으로 삼기 위해서다.

### 확인한 현재 기준

- Markdown 콘텐츠 592개
- GitHub Actions 일일 topic radar 운영
- 자동 원고 발행은 미구현
- Search Console 성과 수집과 Google Ads 전환 추적은 미구현

## 2026-09-18 — 추석 실용 정보 묶음 확장

- 추석 교통·택배·병원·은행·차례·장보기 등 독자의 준비 흐름에 맞춘 관련 글을 추가했다.
- 카테고리가 아니라 독자의 다음 행동을 기준으로 내부 연결하는 원칙을 유지했다.

## 2026-08-15 — 일일 주제 레이더 클라우드 실행

- 로컬 컴퓨터가 꺼져 있어도 보고서를 생성하도록 GitHub Actions 스케줄을 구성했다.
- 자동화 범위는 주제 추천 보고서 갱신까지이며, 글 자동 발행은 포함하지 않는다.

## 2026-08 — 콘텐츠 운영 기준 강화

- 공식 출처, 정보 이득, 짧은 문단, Q/A형 FAQ, 독자의 다음 행동 중심 내부 링크를 표준으로 정했다.
- 의미 없는 편집 원칙 문구, 억지 CTA, 단순 카테고리 기반 시리즈를 지양하기로 했다.
- 썸네일은 모바일에서 이미지 위 제목을 읽을 수 있는 편집형 구성을 기준으로 정했다.
