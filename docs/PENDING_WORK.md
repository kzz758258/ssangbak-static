# SsangBak 추후 작업 체크리스트

Updated: 2026-08-07

아래 항목은 현재 미구현 또는 부분 구현 상태입니다. 다음 작업을 시작할 때 범위와 운영 방식을 먼저 확정한 뒤 진행합니다.

## 우선순위 1 — 실제 예약 공개

- [ ] 미래 `pubDate` 글을 공개 시각 전에는 목록·RSS·사이트맵·개별 URL에서 노출하지 않도록 설계
- [ ] 컴퓨터가 꺼져 있어도 지정 시각에 Cloudflare 배포가 실행되는 클라우드 스케줄러 구성
- [ ] 같은 날 여러 글을 시간차로 공개하는 방식 검증
- [ ] 예약 글의 조기 노출, 타임존, 배포 실패 시 재시도 테스트

현재 상태: 미래 시각의 `pubDate`도 빌드와 동시에 개별 URL이 공개되며, 날짜는 정렬과 작성일 표시에만 사용됩니다.

## 우선순위 2 — 일일 발행 자동화

- [ ] 주제 레이더 → 네이버 리서치 → 공식 출처 검증 → 원고 → 썸네일 → 품질 검사 흐름 연결
- [ ] 자동 발행 전 사람 승인 단계를 유지할지 결정
- [ ] 실패한 출처, 중복 주제, 마감된 공연을 자동 제외
- [ ] 정해진 수량보다 품질 기준을 우선하는 중단 조건 추가
- [ ] 배포 성공·실패 결과와 실제 공개 URL 기록

현재 상태: 각 단계의 도구는 있으나 Codex 요청을 통해 실행하는 반자동 방식이며 cron·GitHub Actions·Cloudflare 예약 작업은 없습니다.

## 우선순위 3 — 검색·트렌드 데이터 확장

- [ ] 네이버에서 활용 가능한 숏콘텐츠 또는 추가 트렌드 데이터 소스의 실제 API 제공 여부 확인
- [ ] 사용 가능할 경우 기존 뉴스·블로그·카페·지식인 데이터와 중복되지 않는 정보만 통합
- [ ] Search Console API 연결 여부 결정
- [ ] 색인 상태, 검색어, 노출, 클릭, CTR, 평균 순위 수집
- [ ] 미색인 글과 성과 개선 대상 글의 자동 점검 보고서 구성

현재 상태: 네이버 검색광고 검색량·연관 키워드, 데이터랩 추세, 뉴스·블로그·카페·지식인 검색은 연결되어 있습니다. Search Console 성과 수집과 색인 감시는 연결되어 있지 않습니다.

## 우선순위 4 — PC 사이드 광고

- [ ] 애드센스 자동 사이드레일 광고 설정 상태 확인
- [ ] 코드에 고정 좌우 광고를 넣을지 자동광고에 맡길지 결정
- [ ] 본문 폭·최신 뉴스 사이드바·화면 크기별 충돌 여부 확인
- [ ] CLS와 모바일 오노출 없이 실제 광고 응답 테스트

현재 상태: 목차 다음, FAQ 직전, 모바일 메인 최신정보 직전 광고와 하단 오버레이 설정은 적용되어 있습니다. PC 좌우 고정 슬롯은 없습니다.

## 진행 원칙

- 글의 정확성·최신성·공식 출처 검증을 자동화 편의보다 우선합니다.
- 마감된 공연, 확인되지 않은 혜택, 기존 글과 같은 검색 의도는 자동 발행하지 않습니다.
- 예약 공개 기능을 먼저 완성한 뒤 완전 자동 발행 범위를 확대합니다.
- 구현 전 현재 운영 중인 Cloudflare·GitHub·애드센스 설정을 다시 확인합니다.
